# TUIT LMS Telegram Bot (Java)

Java + Gradle Telegram bot для TUIT LMS (lms.tuit.uz)

## 📁 Структура

```
src/main/java/uz/tuit/lmsbot/
├── Main.java
├── config/
│   └── AppConfig.java          # Загрузка application.yml
├── model/
│   ├── Course.java
│   ├── AttendanceRecord.java
│   ├── Activity.java
│   └── CourseSummary.java
├── service/
│   ├── LmsService.java         # Вся логика LMS API
│   └── InMemoryCookieJar.java
└── bot/
    └── LmsBot.java             # Telegram bot handler
```

## ⚙️ Настройка

### 1. Создайте бота через @BotFather

### 2. Заполните `src/main/resources/application.yml`:
```yaml
bot:
  token: 1234567890:ABCdefGHI...
  username: my_lms_bot
```

### Или через переменные окружения:
```bash
export BOT_TOKEN=1234567890:ABCdefGHI...
export BOT_USERNAME=my_lms_bot
```

## 🚀 Запуск

```bash
# Собрать fat JAR
./gradlew jar

# Запустить
java -jar build/libs/lms-bot.jar

# Или через Gradle
./gradlew run
```

### 💻 Локально на Windows вместе с мини-приложением

Мини-приложению Telegram нужен публичный https-адрес. `start-local.ps1` поднимает бесплатный
туннель Cloudflare (`*.trycloudflare.com`, без аккаунта; `cloudflared` скачается сам), ставит по
нему webhook и кнопку «LMS» и запускает бота с ограничением памяти (~150–300 МБ).

1. Нужны Java 17+ и Node.js. Соберите:
   ```powershell
   cd webapp; npm ci; npm run build; cd ..
   .\gradlew jar
   ```
2. Создайте рядом файл `.env` (он в `.gitignore`):
   ```
   BOT_TOKEN=1234567890:ABCdefGHI...
   BOT_USERNAME=lmstgbot
   ```
   Токен должен быть тем же, что на хостинге: из него выводится ключ шифрования сессий
   (если не задан `STATE_KEY`), и бот поднимет сессии пользователей из резервной копии в админ-чате.
3. Выключите сервис на хостинге — с одним токеном может работать только один бот.
4. Запустите двойным щелчком `start-local.cmd` или в PowerShell:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\start-local.ps1
   ```
   Остановка — `Ctrl+C`, туннель закрывается вместе с ботом.

Адрес туннеля меняется при каждом запуске: кнопку «LMS» бот обновляет сам, а кнопку
«Открыть» в профиле бота (@BotFather → Bot Settings → Configure Mini App) — вручную.
Компьютер не должен уходить в сон. Вход через OneID работает только с узбекского IP —
локальный запуск из Узбекистана это решает.

## 👨‍🏫 Кабинет преподавателя и тьютора

Роль определяется по меню LMS после входа (`/teacher/…` — преподаватель, переключатель
`/select-role/tutor` — есть группа тьютора) и хранится в `sessions/role_<id>.json`. Код —
`service/TeacherService` (запросы к LMS), `bot/TeacherBot` (меню и диалоги), `web/TeacherApi`
(`/api/t/*`) и `webapp/src/screens/teacher`.

- потоки семестра, календарный план с отметками, посещаемость занятия;
- ведомость и оценивание работ (критерии, комментарий, «убрать оценку»), файлы студентов;
- активности потока: создание (критерии, файл-инструкция) и удаление;
- проверка работ: открытые сроки, непроверенные работы и срок оценивания из ведомости;
- исправление НБ (`/report/attendance`), учебные материалы к темам, итоговые, профиль;
- тьютор: группы, НБ студентов, предметы по семестрам, учебный план, расписание;
- перекличка: тап по паре в расписании (бот и мини-приложение) и кнопка «Перекличка» в «Мои
  предметы» открывают перекличку нужного занятия: тап по студенту ставит или снимает НБ, «Сохранить»
  отправляет её в LMS (после отправки страница перечитывается и сверяется);
- напоминания: пары (расписание строится по датам календарного плана) и сводка дня;
  оценки — раз в 3 часа с закрытия приёма работ до конца срока оценивания (по ведомости LMS,
  по умолчанию 3 дня), пока есть непроверенные работы; перекличка — с начала пары и каждые
  45 минут, пока она идёт (2 раза на паре в 80 минут), после конца пары каждые 2 часа до суток
  или до отметки в календарном плане. У напоминаний об оценках и переклички есть «⏰ Отложить»:
  выбрать минуты или часы и ввести число. У студента то же в напоминании о дедлайне
  («Напомнить через…»).
- кнопка цели в напоминании: пара — перекличка этой пары (преподавателю) или расписание и задания
  предмета (студенту); дедлайн — само задание; оценки — ведомость нужной активности; новый НБ —
  посещаемость предмета.

Подписи полей, статусы, инструкции и виды материалов берутся со страниц LMS, не из кода.
Режим тьютора в LMS живёт в сессии: запросы тьютора идут под исключительным замком
(`LmsService.asTutor`), после них сессия возвращается в режим преподавателя.
Перенос занятий бот не делает — форма этой страницы не разобрана.

## 📱 Mini App

Фронтенд — `webapp/` (React + Vite + framer-motion, иконки lucide). Собирается в
`src/main/resources/webapp` и отдаётся тем же HTTP-сервером, что health-check (`$PORT`):

| Путь | Что |
|------|-----|
| `/` | health-check |
| `/app/` | мини-приложение |
| `/api/*` | JSON API; пользователь — из подписанной `initData` Telegram |

Приложение работает в той же LMS-сессии, что и бот: вход в боте = вход в приложении и наоборот.
Кнопка меню бота ставится автоматически, если есть `WEBAPP_URL` или `RENDER_EXTERNAL_URL`; команда `/app` шлёт кнопку запуска.

```bash
cd webapp && npm ci && npm run build   # затем ./gradlew jar
```

Docker собирает фронтенд сам. Для отладки API без Telegram: `WEBAPP_DEV_USER=<telegram id>` (только локально!).

## 🔁 Сессии и сон хостинга

Бесплатный сервис Render засыпает без входящих запросов, а диск стирается при каждом
деплое и пробуждении. Чтобы вход не приходилось повторять, работают три вещи.

**Webhook.** Апдейт приходит обычным POST на `/tg/<хэш токена>`, поэтому сообщение
пользователя само будит уснувший сервис — при long polling спящий бот просто не
забирает апдейты и молчит, пока его не разбудит кто-то извне. Включается сам, если
известен публичный https-адрес (`WEBHOOK_URL` или `RENDER_EXTERNAL_URL`) и задан `$PORT`.
Путь и заголовок `X-Telegram-Bot-Api-Secret-Token` выводятся из токена бота.

**Токен OneID.** После входа через OneID бот хранит выданный JWT (зашифрован AES-GCM,
ключ из `STATE_KEY`, иначе из токена бота). Когда сессия LMS истекает, бот сам проходит
`sso/v1/generate` → callback и получает новую — пароль нигде не сохраняется и второй
фактор не запрашивается. `/logout` токен стирает.

**Touch LMS.** Раз в 25 минут бот делает по одному запросу за каждого вошедшего: время
простоя сессии обнуляется, и она не истекает вовсе. Работает, только пока сервис не спит.

| Переменная | Что делает |
|------------|-----------|
| `WEBHOOK_URL` | Публичный https-адрес сервиса; на Render берётся `RENDER_EXTERNAL_URL` |
| `WEBHOOK=off` | Принудительно вернуть long polling |
| `STATE_KEY` | Ключ шифрования токенов OneID и резервной копии состояния |
| `KEEPALIVE_URL` | Что пинговать, чтобы сервис не уснул |
| `KEEPALIVE_HOURS` | Окно активности, напр. `7-1`; вне окна сервис засыпает — тогда touch не работает и сессию поднимает токен OneID |

**Пароли не хранятся.** Логин и пароль нужны только в момент входа; «Автовход» убран, а
оставшиеся от него файлы `creds_*.json` стираются при запуске и в резервную копию не попадают.

**`/deletedata`** — пользователь сам стирает всё, что бот о нём знает: сессию, токен OneID,
роль, язык и настройки, запись в списке студентов. Копия в Telegram сразу перезаливается,
а до этого файлы стёртого пользователя при восстановлении из старой копии пропускаются.

Снаружи стоит добавить пингер (UptimeRobot, cron-job.org) раз в 10 минут: разбудить
уже уснувший сервис изнутри нельзя.
